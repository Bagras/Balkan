# Интерфейс: что где лежит и за что можно браться

Записка для того, кто будет переделывать внешний вид. Ядро игры про интерфейс
ничего не знает — его можно переписать целиком, не трогая ни одной строки
в `scripts/core/`.

## Где что

| Файл | Строк | Что внутри |
|---|---|---|
| `scripts/ui/theme.gd` | 55 | **все цвета и стили рамок.** Начинать проще всего отсюда |
| `scripts/ui/main.gd` | 604 | вёрстка и вся логика экранов |
| `scenes/main.tscn` | 10 | почти пустая: узел `Control` со скриптом |

Вёрстка собрана кодом, а не в редакторе. Это было удобно мне (правится из
консоли, не надо синхронизировать сцену с логикой), но тебе может быть неудобно.
**Ядру всё равно** — если хочешь собирать экраны мышью в редакторе, переноси
вёрстку в `.tscn` и выкидывай функции `_build_*`. Ничего не сломается, пока
соблюдён контракт ниже.

## Контракт с ядром

Всё, что интерфейс обязан вызывать. Больше ему ничего не нужно.

```gdscript
var db := ContentDB.new()
var err := db.load_all()          # "" при успехе, иначе текст ошибки

var game := Game.new(db)
game.autosave = true              # интерфейс включает, симулятор и тесты нет
game.start(0)                     # 0 — случайное зерно

# Цикл хода
var presented := game.begin_turn()
#   {} если событий не осталось; иначе:
#   {code, title, description, kind, source, turn,
#    choices: [{index, text, available}]}

var result := game.choose(index)  # {outcome, applied} либо {error}
game.available_actions()          # [{id, title, description, cost, gain,
                                  #   available, cooldown_until}]
game.do_action(id)                # {applied, title} либо {error}

var ending := game.end_turn()     # {} если игра продолжается,
                                  # иначе концовка, либо {error}
game.get_ending()                 # {id, kind, title, text, turn, stats,
                                  #  key_moments, defeat_reason?}
```

Состояние для панели показателей:

```gdscript
game.state.stats                  # {ключ шкалы: int}
game.state.turn
game.state.phase                  # GameState.Phase.{READY, CHOICE, CABINET, OVER}
game.state.history                # [{turn, event, title, choice, choice_text}]
game.state.effect_multiplier      # нужен, чтобы показывать реальную цену действий
```

Справочники:

```gdscript
db.config["stats"][key]           # {label, short, start, fatal, group?}
db.config["mandate_turns"]
db.stat_help(key)                 # текст подсказки к шкале
db.help                           # {briefing: {title, text}, sections: [...]}
SaveGame.has_save() / load_into(game) / clear()
```

**Порядок вызовов жёсткий:** `begin_turn` → `choose` → (необязательно
`do_action`) → `end_turn`. Ход нельзя закрыть, пока событие не разрешено, —
`end_turn` вернёт `{error}`, и это не баг, а защита от зацикливания.

## Экраны, которые должны быть

1. **Продолжение** — если `SaveGame.has_save()`. Без него прерванная партия недостижима.
2. **Вводный экран** — `db.help["briefing"]`, перед первым ходом.
3. **Событие** — текст и три кнопки; недоступные варианты (`available == false`)
   надо показывать заблокированными, а не прятать: игрок должен видеть, что
   вариант есть, но не для его показателей.
4. **Исход и кабинет** — текст последствия, изменения шкал, действия, конец хода.
5. **Концовка** — текст, причина поражения, ключевые решения партии.
6. **Журнал и справка** — накладки поверх текста.

## Что сломает тесты

`tests/ui_smoke.gd` проходит партию, нажимая настоящие кнопки, и обращается
к полям по именам:

```
main.game   main.mode   main._body        main._title_label
main._choice_box   main._cabinet_box   main._footer
main._stats_box    main._journal_button   main._help_button
```

Переименуешь или уберёшь — тест упадёт. Это не повод их не трогать: просто
поправь и тест, он на 150 строк и читается насквозь. **Ронять его насовсем
не стоит** — он уже дважды ловил то, чего не видно глазами: наложение строк
в панели показателей и рассинхрон сохранения на один ход.

## Как смотреть результат без редактора

```bash
xvfb-run -a -s "-screen 0 1600x900x24" godot --path . \
  --resolution 1600x900 --script res://tools/screenshot.gd
```

Кладёт `shot_briefing`, `shot_event`, `shot_cabinet`, `shot_help` в корень
проекта (в репозиторий они не коммитятся). Полезно, чтобы сравнить «до и после»
на одном и том же месте партии.

## Про карту страны

Если дойдёт до неё: данные для карты **уже есть**, дописывать в ядро ничего
не нужно. Общины привязаны к регионам сеттингом — сербы это восток, центр
и север Стари-Брода, албанцы юг и Пласа, греки побережье с двумя портами
и Ано-Кастро. Цвет региона берётся из `game.state.stats["loyalty_*"]`,
линия раздела — из истории: `Т-3` с выбором III или `Т-9` с выбором II
(см. условие концовки «Раздел» в `content/endings.json`).
